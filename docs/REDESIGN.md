# Open game.ai 界面设计与延展路线

## 1. 设计语言

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 材质 | Liquid Glass：半透明填充 + `blur(30px) saturate(175%)` + 1px 顶部高光描边 | 层级靠模糊半径表达，而不是厚重阴影 |
| 光源 | 全局只有一个光源：缓慢漂移的极光光斑（紫 / 蓝 / 品红）+ 点阵网格 + 噪点 | 让所有玻璃面板有东西可"折射"，画面有呼吸感 |
| 字体 | SF Pro 用于阅读；SF Mono 只用于"机器事实"：路径、线程 id、耗时、版本 | 极客感来自信息本身，而不是装饰 |
| 颜色 | 颜色只表达状态：紫→青 = Agent 工作中，薄荷绿 = 已验证，琥珀 = 等待，玫红 = 需处理 | 一眼读懂系统状态 |
| 动效 | `cubic-bezier(0.22, 1, 0.36, 1)`；输入框聚焦时亮起锥形光环；页面切换改为毛玻璃溶解 | 克制、有物理感，并尊重 `prefers-reduced-motion` |

实现方式：`src/renderer/glass.css` 作为独立设计层，全部挂在 `html[data-ui='glass']` 下。它将设计 token 统一映射为玻璃界面样式，各组件共享颜色、字体和层级规则。

## 2. 工作台交互

- **⌘K 命令面板**（`CommandPalette.tsx`）：模糊搜索游戏、操作和设置，支持完整键盘操作。
- **Mission Control 制作控制台**（`ProductionConsole.tsx`）：八个阶段环绕进度环，并显示实时遥测（耗时 / 事件 / 工具调用 / 文件）、当前动作和日志尾部。像素工坊作为可切换的制作视图。
- **首页 Agent Loop 图示**：直接画出 Planner → Implementer → Reviewer → Build → Playtest ↺×3 这条闭环，也就是产品最大的差异点。
- **浏览器 Demo 模式**（`demo/demoRuntime.ts`）：不在 Electron 中运行时，自动接管 `window.opengame`，回放一条完整的制作流程，右侧是一个真实可玩的小游戏。访问者无需登录 Codex 即可体验示例流程。
- **启动序列**：毛玻璃卡片配合终端风格 boot log，清楚展示启动状态。

本地预览：`npx vite --host 127.0.0.1 --port 5174`，然后打开 http://127.0.0.1:5174

## 3. 延展功能建议

1. **Prompt → 设计简报确认卡**：Planner 产出 GDD 后先停一下，生成一张可编辑的"玩法卡"（核心循环、操作、胜负、美术风格），用户确认后再进入实现。这能减少无效生成，也是一个很好讲的"人在回路"设计点。
2. **版本时间轴 + 一键回滚**：每轮 Reviewer 通过就自动生成 git 快照，时间轴上显示缩略截图，可以 A/B 对比两个版本。
3. **体验评测可视化**：把自动试玩的截图帧做成胶片条，同时展示六项检查的雷达图，再加上"为什么扣分"的自然语言解释。
4. **成本与时长透明化**：每轮显示 token 消耗、预计剩余时间和素材 API 调用次数，并支持设置预算上限。这对应文档里"费用不透明"的痛点。
5. **Remix 社区 / 模板市场**：把通过门禁的游戏导出成模板，其他人一句话就能 Remix，形成增长闭环。
6. **一键发布**：Web 构建一键部署成可分享链接，附带二维码，手机扫码即玩。
7. **多 Agent 并行可视化**：素材生成和代码实现并行跑，控制台上显示多条轨道（像 CI 流水线那样）。
8. **语音 / 草图输入**：拍一张手绘关卡草图，或者直接用语音描述，作为创意输入。

## 4. 设计原则

- 视觉改版的出发点是让 **AI 的工作过程可被观察和信任**，好看是结果，不是目的。控制台、遥测、终端事件流，都是为了把黑盒变成白盒。
- Demo 模式体现了**降低体验门槛**的产品意识：评估者不需要账号就能完整走通流程。
- 设计层保持可插拔，业务状态与显示样式分离；界面变更通过类型检查、测试和生产构建验证。
